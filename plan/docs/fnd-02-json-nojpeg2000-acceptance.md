## F02-07 maintenance-policy binding

This successor selects exact owned revisions, modified source, retained archives,
build inputs, toolchain identities and output artifacts. AmbisGIS maintains repair
capability for its selected code; required core custody is unchanged. New donor
releases, security disclosures or patches are advisory inputs to AmbisGIS's own
triage. A component change, import, backport or independent repair requires a
reviewed source change, affected tests and an updated authoritative manifest.
There is no automatic donor synchronization, floating production input,
unrecorded download, or permission to freeze a known insecure version indefinitely.

The Java/server proposal explicitly excludes Oracle support, renderer OpenGL
paths and optional JPEG2000 handling. Reintroducing one of these capabilities
requires its own source/terms selection and affected tests; a dependency update
cannot silently enable it. No native OpenJPEG Java wrapper is selected here.
[The dated comparison](jpeg2000-exclusion-handoff.md) records why removal better
matches the owner's priorities and avoids new native codec/wrapper maintenance.
Unrelated QGIS/GDAL/notebook profiles are not altered for naming consistency.

The JSON compatibility boundary remains finite: maintain the actual selected
public/reflective protocols, bounded nesting/malformed-input behavior and safe
BeanUtils class-property suppression. Do not restore unsafe introspection or
introduce arbitrary polymorphic typing/class loading to satisfy an old test.
The original JSON/JJ2000 sources, predecessor variants and failed receipts remain
unchanged evidence, with their original rights and limitations.

This is the existing chapter 11/chapter 08 rule bound to the successor, not a
new upstream support promise or a waiver of source, security, copyright, notice,
trademark or release obligations. The linked explicit owner decision accepts
this F02-07 binding and C4 for the exact unchanged candidate.
